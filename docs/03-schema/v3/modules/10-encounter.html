OPD Encounter

The aggregate root for an outpatient visit. op_visits is the umbrella that consultations, lab orders, radiology orders, and invoices all hang off. patient_states is the single log of every stage a patient passes through — one row per station entry, left_at = NULL means the patient is currently there.

Module 10 contents — one table at a time
  1. op_visits — one row per OP encounter; chief complaint, doctor, current state (trigger-synced)  signed off
  2. patient_states — append log of every station the patient visits; left_at IS NULL = currently there; partial unique index enforces one active row per visit  signed off

1. op_visits mutable L1 audit L3 audit soft-delete

One row per outpatient encounter. Created the moment a patient is registered for today's visit (walk-in) or checks in against a booked appointment. Everything clinical hangs off this row — consultations, vitals, prescriptions, lab orders, radiology orders, and invoices all FK back to op_visits.id.

The current stage of a visit is always derivable from patient_states WHERE op_visit_id = this.id AND left_at IS NULL — no denormalised status column on op_visits. Business cancellation is tracked by setting closed_at; soft-delete is reserved for data-error correction only.

Forward FK note: appointment_id references appointments(id) defined in Module 09. The column is included here; the FK constraint is added in the Module 09 migration.

2. patient_states mutable L1 audit L3 audit soft-delete

Append log of every stage a patient passes through after payment. Tracking starts the moment op_visits is created (i.e. consultation fee paid, OP number issued). Before that, the patient's state lives in appointments.status (arrived). A patient who arrives but never pays will never have a row here.

One row per station entry. left_at = NULL means the patient is currently at that station. left_at IS NOT NULL means they have moved on. Duration at any stage = left_at − entered_at.

The partial unique index uq_patient_states_one_active is the key safety constraint — the DB rejects any INSERT that would create a second active row for the same visit. If application code has a bug, Postgres blocks it before data is corrupted.

First row: always Vitals — inserted in the same transaction that creates op_visits after payment succeeds. Billing (for mid-visit test/service fees) and other stations appear as the visit progresses. The initial consultation fee is tracked in payment_attempts → payments, not here.

Transition pattern: when a patient moves from Vitals to Doctor, the application runs two writes in one transaction: (1) UPDATE the current active row — set left_at = now(); (2) INSERT a new row for the next station with left_at = NULL. There is never a moment where two active rows exist for the same visit.

Multiple visits same day: each OP visit (morning + evening) has its own op_visit_id. The partial unique index is scoped to op_visit_id, so both visits independently have one active row each.

Historical lookup: patient_states JOIN op_visits ON op_visits.id = op_visit_id WHERE op_visits.visit_date = :date AND patient_id = :id ORDER BY entered_at.

Constraints & Indexes
  • pk_patient_states — PRIMARY KEY (id)
  • uq_patient_states_one_active — UNIQUE INDEX (op_visit_id) WHERE left_at IS NULL — DB enforces: at most one active stage per visit at any time. INSERT of a second active row is rejected.
  • ix_patient_states_visit — INDEX (op_visit_id, entered_at ASC)  — full stage history for a visit, chronological
  • ix_patient_states_station_active — INDEX (station_id, entered_at ASC) WHERE left_at IS NULL  — live queue board: everyone currently at this station, oldest first
  • ix_patient_states_patient_active — INDEX (patient_id) WHERE left_at IS NULL  — where is this patient right now
Triggers
  • tr_patient_states_bu_touch — BEFORE UPDATE → fn_touch_updated()
  • tr_patient_states_au_audit — AFTER INSERT/UPDATE/DELETE → fn_audit_row()

Query — where is Meena right now?
SELECT station_id, entered_at FROM patient_states WHERE op_visit_id = '…ov001' AND left_at IS NULL → ps005 (Doctor, since 11:30).

Query — Meena's full journey today?
SELECT s.display_name, ps.entered_at, ps.left_at FROM patient_states ps JOIN stations s ON s.id = ps.station_id WHERE ps.op_visit_id = '…ov001' ORDER BY ps.entered_at → all 5 rows in order.
