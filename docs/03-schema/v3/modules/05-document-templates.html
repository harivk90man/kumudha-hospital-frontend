v3 Schema Module 05 · Document Templates

Document Templates

Admin-managed HTML templates rendered by the app at print time — prescription printouts, invoice PDFs, discharge summaries, and similar patient-facing documents.

File attachments decision: A central polymorphic file_attachments table was considered and dropped — no FK means no lifecycle management (orphans on entity delete). File references are handled per entity in their owning module:
  • doctor_profiles.signature_path — one signature per doctor (already in Slice 1B)
  • lab_results.report_path — one report PDF per result (Module 12)
  • radiology_study_files — N DICOM images per study, child table with FK CASCADE (Module 13)

1. document_templates mutable L1 audit L3 audit soft-delete

Catalogue of document templates managed by the admin. The app fetches a template by template_code at print/send time, injects the runtime variables, and produces the final output (PDF, HTML, SMS text). Soft-deleting a template is safe — already-rendered documents are static files and hold no reference back to this table.

JSON shape — variables column
KeyTypeMeaning
requiredarray of stringVariable names the app MUST inject before rendering. App raises if any are missing.
optionalarray of stringVariable names the app MAY inject. Template handles their absence gracefully (e.g. hides the signature block if doctor_signature_path is not provided).
 
{
  "required": ["doctor_name", "patient_uhid", "medicines", "hospital_name"],
  "optional": ["doctor_signature_path", "follow_up_date"]
}
Constraints & Indexes
  • pk_document_templates — PRIMARY KEY (id)
  • uq_document_templates_code — UNIQUE (template_code) WHERE deleted_at IS NULL  — partial: allows a new version of a retired template with the same code
  • chk_document_templates_code_len — CHECK char_length(template_code) BETWEEN 2 AND 80
  • chk_document_templates_type — CHECK template_type IN ('pdf','html','sms','email')
  • ix_document_templates_type — INDEX (template_type) WHERE deleted_at IS NULL
Triggers
  • tr_document_templates_bu_touch — BEFORE UPDATE → fn_touch_updated()
  • tr_document_templates_au_audit — AFTER INSERT/UPDATE/DELETE → fn_audit_row()
