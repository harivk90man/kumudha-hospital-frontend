v3 Schema Module 17 · Billing

Billing & Invoicing

The invoice as a business artefact — bill header and line items with GST split. Every billable item from every module resolves to an invoice line here.

What lives here vs Module 18: invoices records what was billed. payments (Module 18) records how it was paid. They are linked via payment_allocations (Module 18).
Discount pattern: same as pharmacy_sales — bill_discount_pct (nullable %) + bill_discount_amount (always ₹). bill_discount_type dropped.
Generated columns: invoices.balance and invoices.total_discount are GENERATED ALWAYS AS … STORED — balance can never silently drift.
Module 17 contents
  1. invoices — bill header; totals, GST, discount, balance, idempotency; L2 maker-checker for discount approval  locked
  2. invoice_items — bill lines; item type discriminator; separate-column source FKs; GST split  locked
  3. credit_notes — dropped. Payment-before-service model means no write-offs. No store credit (refund-only policy). Pharmacy return refunds traced via payments.pharmacy_return_id (payment_direction = 'out', Module 18). Over-collection corrections handled as reverse payments in Module 18.

1. invoices mutable L1 audit L2 maker-checker L3 audit soft-delete

Bill header — one per billing event. Every paid service (OPD consultation, lab order, radiology, pharmacy sale) links to an invoice row. Carries the full financial summary: subtotal, discounts, GST, total, amount paid, and outstanding balance. Layer 2 maker-checker governs discount approval per BRD §9 — when total discount exceeds system_config.billing.discount_threshold_for_approval, the invoice moves to pending_approval and payment is blocked until a second person approves.

v3 delta from TSD-12: tenant_id dropped. bill_discount_type + bill_discount_value replaced by bill_discount_pct (nullable) + bill_discount_amount — same pattern as pharmacy_sales and pharmacy_sale_items. invoice_date kept — financial reporting date, may differ from created_at (e.g. late-night service billed next morning). balance and total_discount are GENERATED ALWAYS AS columns — can never drift.

  • ix_invoices_overdue — INDEX (payment_status, balance) WHERE balance > 0 AND payment_status NOT IN ('cancelled','written_off','draft') AND deleted_at IS NULL  — overdue dashboard

Triggers

2. invoice_items mutable L1 audit L3 audit

Bill lines — one row per billable item. Each line has an item_type discriminator and a separate-column FK to the source business object (consultation, lab order item, radiology order, pharmacy sale item). GST split is per line. On INSERT/UPDATE/DELETE, a trigger recomputes the parent invoices totals atomically.

v3 delta from TSD-12: tenant_id dropped. item_type CHECK extended to include lab_panel (matching services.service_type). Phase 2 FKs (bed_assignment_id, surgery_schedule_id) kept as nullable placeholders. Immutable once parent invoice payment_status = 'finalized'.

credit_notes — dropped.
  • No write-offs — payment-before-service model means patients cannot leave without paying. Write-offs are theoretically impossible.
  • No store credit — refund-only policy chosen. Store credit requires a patient wallet with expiry tracking — out of scope.
  • Pharmacy return refunds — traced via payments.pharmacy_return_id (payment_direction = 'out', Module 18). Full traceability: payment → pharmacy return → return items → original sale.
  • Over-collection corrections — handled as a reverse payment (payment_direction = 'out') in Module 18.
