v3 Schema Module 01 · Slice 1B of 4 · Organisation

Organisation

The hospital's org chart — functional units (departments) and the doctor-specific extension that hangs off users.

Slice 1B contents
  1. departments — functional units (Ortho, Cardio, Lab, Pharmacy, …)
  2. doctor_profiles — clinical extension of users; source of truth for consultation fees
  3. doctor_leaves — individual doctor leave / unavailability days; appointment slot generator checks this before creating slots
  4. doctor_registrations — N:1 child of users; one row per (doctor × medical council). Supports state council + NMC + historical state regs.
  5. department_heads — formal department roles (head / co_head / senior / junior / registrar / intern), with history

1. departments mutable L1 audit L3 audit soft-delete

Functional units of the hospital (Orthopaedics, Cardiology, Lab, Pharmacy, …). Drives staff routing, dept-wise revenue rollups, approval scoping, and the doctor picker in the appointment booking UI. Each user belongs to a primary department (nullable for cross-cutting roles like the platform-admin role). Department leadership (head / co-head / acting-head) and formal ranks (senior / junior / registrar / intern) live in the separate department_heads table — not on this table.

2. doctor_profiles mutable L1 audit L3 audit soft-delete

Doctor-specific extension of users (1:1, mandatory UNIQUE user_id). Drives consultation pricing (source of truth per v3 Resolution 1 — see "Pricing" callout below), appointment slot length, follow-up free-window logic, the doctor's weekly availability template, and the digital-signature image embedded on prescriptions.

Pricing model — Resolution 1 locked. Consultation fees live HERE in doctor_profiles. The future services table (Module 16) will hold generic per-category rows (CONSULT_NEW, CONSULT_FU, ECG, ROOM_PVT, …) with default_price = NULL for the two consultation service types. At billing time, the invoice-line service-layer code looks up the doctor's consultation_fee / follow_up_fee here and snapshots it into invoice_items.unit_price. The services table has no doctor_id column (dropped from v2).
Columns (table-specific)

Shared-PK pattern: user_id is BOTH the primary key AND the foreign key to users(id). No separate surrogate id column. This enforces strict 1:1 at the schema level (a user has at most one doctor_profiles row by virtue of the PK), saves one index, and the FK constraint guarantees no orphan rows. Same pattern will be applied to user_preferences in Slice 1D. See CONVENTIONS.md §2a for full rationale.

DB-side validator — fn_validate_available_days(jsonb)
CREATE OR REPLACE FUNCTION fn_validate_available_days(p jsonb)
RETURNS boolean LANGUAGE plpgsql IMMUTABLE AS $$
DECLARE
  k        text;
  window   jsonb;
  hh_mm    text := '^([01][0-9]|2[0-3]):[0-5][0-9]$';
  allowed  text[] := ARRAY['mon','tue','wed','thu','fri','sat','sun'];
BEGIN
  IF jsonb_typeof(p) <> 'object' THEN RETURN false; END IF;

  FOR k IN SELECT jsonb_object_keys(p) LOOP
    IF NOT k = ANY(allowed)                                              THEN RETURN false; END IF;
    IF jsonb_typeof(p->k) <> 'array'                                     THEN RETURN false; END IF;

    FOR window IN SELECT jsonb_array_elements(p->k) LOOP
      IF jsonb_typeof(window) <> 'object'                                THEN RETURN false; END IF;
      IF NOT (window ? 'from' AND window ? 'to')                         THEN RETURN false; END IF;
      IF NOT ((window->>'from') ~ hh_mm AND (window->>'to') ~ hh_mm)      THEN RETURN false; END IF;
      IF (window->>'from')::time >= (window->>'to')::time                THEN RETURN false; END IF;
    END LOOP;
  END LOOP;

  RETURN true;
END $$;

3. doctor_leaves mutable L1 audit L3 audit soft-delete

Individual doctor leave / unavailability days — distinct from hospital-wide holidays (Slice 1D). One row per (doctor × date) covers the specific days a doctor will not be seeing patients, regardless of their regular weekly schedule.

Slot generator availability check combines three layers:
  1. holidays — hospital closed; no slots for anyone on that date.
  2. doctor_profiles.available_days — the doctor's regular weekly template (Mon–Sun windows).
  3. doctor_leaves — individual exceptions; a leave row for a given date suppresses all slots for that doctor on that date, even if the weekday template is normally open.

4. doctor_registrations mutable L1 audit L3 audit soft-delete

Medical-council registrations held by clinical staff. One row per (doctor × council). Replaces the single doctor_profiles.registration_number column from the earlier v3 draft. Supports the actual Indian regulatory reality:

  • State Medical Council (TNMC / KMC / MMC / …) — mandatory to practise in that state.
  • NMC (National Medical Commission) — federal registry, replaced MCI in 2019. Most doctors hold it alongside their SMC.
  • Historical state registrations — a doctor who moved from Karnataka to Tamil Nadu keeps the KMC row as status = 'historical' and adds a fresh TNMC row.
  • AFMS (Armed Forces Medical Services) — for ex-military doctors, in addition to civilian registrations.

Non-clinical staff have no rows in this table. The users table holds no registration data — the registration concern is fully owned here.

5. department_heads mutable L1 audit L3 audit soft-delete

Formal department roles for clinical staff — head, co-head, acting-head, senior consultant, junior consultant, registrar, intern. Many-to-many between users and departments with started_at / ended_at for history.

Replaces v2's departments.head_doctor_id column. Supports:

  • Multi-rank per dept — Ortho has 1 head (Priya) + 1 junior consultant (Aarthi); could have more senior/junior/registrar/intern rows.
  • Multi-dept per doctor — a senior doctor could be head of two departments (HOD Ortho + HOD Sports Medicine), with two rows.
  • History — when leadership changes, set ended_at on the outgoing row and INSERT a new row for the successor; both rows persist so "who was head of Cardio on 2025-06-01?" is a simple WHERE clause.
  • Eliminates the cyclic FK — departments no longer points back at users; the only cross-table FK now flows users.department_id → departments(id).

Non-clinical staff (administrator, receptionist, pharmacist, lab tech) have no rows in this table — their job titles live in users.designation (free text). This table is the structured catalogue of clinical ranks only.

  • departments.tenant_id column dropped (v2 → v3)

  • departments.segment CHECK list locked: clinical / lab / pharma / radiology / support / er / inpatient

  • doctor_profiles.registration_number dropped — replaced by the new doctor_registrations N:1 child table (state council + NMC + historical regs all first-class rows)
  • New table doctor_registrations — N:1 child of users; UNIQUE on (council, registration_number); partial UNIQUE for at-most-one-active-primary-per-doctor; status enum (active / lapsed / revoked / historical)
  • New table department_heads — M:N between users + departments with role_type, history (started_at/ended_at), and partial UNIQUE for at-most-one-active-head-per-dept
  • Cyclic FK eliminated — only one direction now: users.department_id → departments(id)
