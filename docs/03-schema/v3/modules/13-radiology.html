v3 Schema Module 13 · Radiology

Radiology

Imaging operations — X-ray, ultrasound, CT, MRI. Procedure catalogue, order header, DICOM study metadata bridge to PACS, and radiologist report with maker-checker sign-off.

Centralized pricing (same pattern as Module 12 Lab): radiology_procedures.service_id → services(id). All radiology prices live in services (Module 16). payment_required_before_service dropped from radiology_orders — payment-before-service is universal and governed by system_config.billing.payment_before_service = true.
Single radiologist: the CHECK (created_by <> approved_by) on radiology_reports is present by default. Small hospitals with a single radiologist can relax it via system_config key radiology.allow_self_approval = true — that key change itself goes through the Layer 2 maker-checker on system_config.
Module 13 contents — one table at a time
  1. radiology_procedures — procedure catalogue; modality, body part, service_id for pricing  signed off
  2. radiology_orders — order header; priority, status, invoice link  signed off
  3. radiology_attachments — files uploaded by technician against the order: X-ray images, PDFs, scanned docs (multiple per order)  signed off
  4. radiology_reports — radiologist findings + impression; L2 maker-checker for senior sign-off  signed off
  5. radiology_studies — dropped — DICOM/PACS bridge not needed; technician uploads images directly via app UI

1. radiology_procedures mutable L1 audit L3 audit soft-delete

Reference catalogue of every imaging procedure the hospital performs. Drives the order-creation UI and pricing via service_id → services. Flyway-seeded with common procedures; admin can add hospital-specific ones.

2. radiology_orders mutable L1 audit L3 audit

One order = one act of ordering one imaging procedure. Unlike lab, radiology does not have a separate items table — each procedure is its own order row. Multi-procedure requests (e.g. "CXR + USG abdomen on the same visit") are two separate radiology_orders rows — this matches how radiology worklists are built and how DICOM accession numbers are assigned (one per order).

v3 delta from TSD-09: tenant_id dropped. payment_required_before_service dropped — governed by system_config. ordered_at dropped — use created_at from L1 audit. ip_admission_id retained as a nullable forward FK (Phase 2 IP billing).

3. radiology_attachments mutable L1 audit L3 audit

Files uploaded by the radiology technician against a radiology_orders row. One row per file — multiple files per order are common (PA view + lateral view for CXR; multiple frames for USG; a scanned referral letter; a prior-study PDF for comparison). The radiologist reviews these attachments before writing the report in radiology_reports.

Files supported: X-ray images (image/jpeg, image/png), scanned documents (image/jpeg, image/png), radiology reports from external centres (application/pdf). The file_type MIME column records the format; the app enforces an allowlist at upload time.

v3 design note: replaces radiology_studies from TSD-09 — no PACS/DICOM integration; technician uploads directly through the app UI. file_data bytea stores the file in the DB for v1 (same pattern as lab_results.report_data and radiology_reports.report_data); migrate to S3 later by adding file_url text without touching existing rows.

4. radiology_reports mutable L1 audit L2 maker-checker L3 audit

The signed clinical document — radiologist's findings, impression, and recommendations. Carries Layer 2 maker-checker: junior radiologist dictates → consultant verifies and approves → report is released to the ordering doctor. Supports an amendment chain via amended_from_report_id self-FK — when a released report needs correction, a new row is created referencing the original; the original row's status moves to amended.

Separation-of-duties note: CHECK (created_by <> approved_by) is present by default. For single-radiologist hospitals, set system_config key radiology.allow_self_approval = true; the app skips the CHECK enforcement in that case. The flag change itself requires Layer 2 approval on system_config.

v3 delta from TSD-09: tenant_id dropped. study_id dropped — images live in radiology_attachments linked to the order; the report references the order directly. report_attachment_id changed to report_data bytea — report PDF stored directly in DB for v1 (same pattern as lab_results.report_data); migrate to S3 later by adding report_url text.
