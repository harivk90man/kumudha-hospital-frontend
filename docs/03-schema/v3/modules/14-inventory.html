v3 Schema Module 14 · Inventory

Inventory

Drug supply chain — supplier registry, medicine catalogue, batch-level stock, purchase orders, stock movement ledger, and the NDPS Act narcotic register.

Pricing note: Medicine prices are batch-level (drug_stock.selling_price ≤ MRP), not catalogue-level. The centralized services table (Module 16) covers consultations, lab tests, and radiology — not drug_catalogue. FEFO (First Expiry First Out) is the dispense rule: always pick the batch with the earliest expiry date first.
Narcotic rule: Any transaction involving a drug_catalogue.is_narcotic = true drug must insert a paired narcotic_register row in the same transaction — enforced by trigger.
Module 14 contents — one table at a time

  2. vendor_contacts — one row per contact person per vendor (sales rep, delivery, accounts)  signed off

1. vendors mutable L1 audit L3 audit soft-delete

Supplier registry — pharmaceutical distributors and consumables suppliers. Soft-delete keeps historical PO and batch references intact when a supplier relationship ends. The is_narcotic_supplier flag gates Schedule X purchase orders — a trigger blocks narcotic POs pointing at a non-narcotic vendor. Contact persons (sales rep, delivery, accounts) live in the child table vendor_contacts.

3. drug_catalogue mutable L1 audit L3 audit soft-delete

Drug catalogue — the "what can be prescribed and dispensed" reference. Drives three critical runtime behaviours: (1) allergy alerting at prescribing time via drug_class matched against patient_allergies; (2) narcotic register enforcement — any transaction on a row where is_narcotic = true must insert a paired narcotic_register row in the same transaction (trigger-enforced); (3) FEFO stock check at dispense — the doctor's prescribing UI shows In Stock / Low / Out of Stock by joining to drug_stock.

Pricing note: medicine prices are batch-level (drug_stock.selling_price), not catalogue-level. No service_id FK here — pharmacy billing uses pharmacy_sale_items.unit_price snapshotted from the batch at dispense time.

v3 delta from TSD-10: tenant_id dropped. is_active boolean replaced by deleted_at soft-delete. All other columns kept as specified.

4. drug_stock mutable L1 audit L3 audit

Batch-level stock — the single source of truth for "what can we dispense right now?" Every physical delivery of a medicine creates one row here. FEFO (First Expiry First Out) pick order is enforced at dispense time by sorting active batches by expiry_date ASC. Optimistic-lock version (from L1 audit) prevents lost decrements when two pharmacists dispense from the same batch concurrently.

No soft-delete on this table — batches are financial and compliance records. Instead, is_blocked = true marks a batch as unavailable for dispense (expired, recalled, damaged) while keeping the row for audit. Hard DELETE is blocked by downstream RESTRICT FKs from pharmacy_sale_items and drug_stock_ledger.

v3 delta from TSD-10: tenant_id dropped. All other columns kept. The nightly expiry-block job sets is_blocked = true where expiry_date < current_date; an additional BEFORE INSERT trigger on pharmacy_sale_items also guards against race conditions by rejecting a blocked batch at dispense time.

5. purchase_orders mutable L1 audit L2 maker-checker L3 audit

Purchase order header to a vendor. Carries Layer 2 maker-checker — POs above the requesting staff's spending limit require a second person to approve before the PO is sent to the vendor (BRD §12 approval matrix, configurable via system_config). One PO → many line items in purchase_order_items. When goods arrive, batches are created in drug_stock and drug_stock_ledger rows are appended.

v3 delta from TSD-10: tenant_id dropped. ordered_at dropped — use created_at from L1 audit. All other columns kept. includes_narcotics is recomputed by a trigger on purchase_order_items INSERT — no manual maintenance needed.

6. purchase_order_items mutable L1 audit L3 audit

PO line items — one row per drug per PO. Tracks ordered quantity vs received quantity for partial-receipt scenarios (vendor delivers in multiple trips). GST is split into CGST + SGST (intra-state) or IGST (inter-state) per Indian GST rules — both amount and percentage stored so the purchase invoice can be reconstructed exactly.

v3 delta from TSD-10: tenant_id dropped (inherited from parent PO). ON DELETE CASCADE from purchase_orders — if a draft PO is hard-deleted, its lines go with it. A trigger on INSERT recomputes purchase_orders.total_amount and sets purchase_orders.includes_narcotics = true if the added medicine is narcotic.

7. drug_stock_ledger append-only L1 audit L3 audit
