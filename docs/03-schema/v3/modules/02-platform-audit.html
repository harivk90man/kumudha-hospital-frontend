1. audit_logs append-only L1 audit (cosmetic) L3 — IS the audit store

Central forensic log. Every INSERT / UPDATE / DELETE on any Tier-1 table fires fn_audit_row() which writes one row here capturing the full before/after JSONB snapshot. Append-only — fn_append_only_guard raises an exception on any UPDATE or DELETE attempt. No FK back to entity rows (would block legitimate hard-deletes); orphan check runs as a nightly CI job.

Partitioned by range on created_at (the uniform audit column doubles as the partition key here — no separate occurred_at column needed) — one child partition per calendar month (audit_logs_2026_01, audit_logs_2026_02, …). Old partitions can be detached and archived without touching the parent table.

Note: fn_audit_row() was a no-op stub in Slice 1A (Module 01). This module replaces its body with the real implementation shown in the Triggers section below.

JSON shape — before_state and after_state

Both columns hold the result of to_jsonb(OLD) / to_jsonb(NEW) — a full row snapshot. The shape varies per entity_table; no typed POJO. Two notes:

  • Secret redaction: if the changed table is system_config and is_secret = true, the trigger replaces config_value in the snapshot with "***REDACTED***" before inserting.
  • Password redaction: if the changed table is users, the trigger replaces password_hash and mfa_secret with "***REDACTED***" in both snapshots.

Constraints & Indexes
  • pk_audit_logs — PRIMARY KEY (id, created_at)  — composite with partition key required by Postgres partitioning
  • chk_audit_logs_entity_table_len — CHECK char_length(entity_table) BETWEEN 2 AND 64
  • chk_audit_logs_action — CHECK action IN ('INSERT','UPDATE','DELETE')
  • ix_audit_logs_entity — INDEX (entity_table, entity_id, created_at DESC)  — "full history of row X on table Y" — created on each partition
  • ix_audit_logs_actor — INDEX (actor_id, created_at DESC) WHERE actor_id IS NOT NULL  — "everything user Z did" — created on each partition
Triggers & Functions

fn_append_only_guard() — blocks UPDATE/DELETE on append-only tables:

CREATE OR REPLACE FUNCTION fn_append_only_guard()
RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN
  RAISE EXCEPTION 'Table % is append-only. UPDATE/DELETE are not permitted.',
    TG_TABLE_NAME;
END $$;

fn_audit_row() — replaces the Slice 1A stub. Reads the actor from the session variable set by the app (SET LOCAL app.current_user_id = :userId). Redacts sensitive fields before storing:

CREATE OR REPLACE FUNCTION fn_audit_row()
RETURNS trigger LANGUAGE plpgsql AS $$
DECLARE
  v_before   jsonb := CASE WHEN TG_OP = 'INSERT' THEN NULL ELSE to_jsonb(OLD) END;
  v_after    jsonb := CASE WHEN TG_OP = 'DELETE' THEN NULL ELSE to_jsonb(NEW) END;
  v_actor    uuid  := NULLIF(current_setting('app.current_user_id',   true), '')::uuid;
  v_session  uuid  := NULLIF(current_setting('app.current_session_id', true), '')::uuid;
BEGIN
  -- Redact sensitive columns
  IF TG_TABLE_NAME = 'users' THEN
    v_before := v_before - 'password_hash' - 'mfa_secret'
                || '{"password_hash":"***REDACTED***","mfa_secret":"***REDACTED***"}';
    v_after  := v_after  - 'password_hash' - 'mfa_secret'
                || '{"password_hash":"***REDACTED***","mfa_secret":"***REDACTED***"}';
  END IF;
  IF TG_TABLE_NAME = 'system_config' AND (to_jsonb(COALESCE(NEW, OLD))->>'is_secret')::boolean THEN
    v_before := v_before - 'config_value' || '{"config_value":"***REDACTED***"}';
    v_after  := v_after  - 'config_value' || '{"config_value":"***REDACTED***"}';
  END IF;

  INSERT INTO audit_logs
    (id, entity_table, entity_id, action, actor_id, session_id,
     before_state, after_state,
     created_by, created_at, updated_at)
  VALUES
    (uuidv7(),
     TG_TABLE_NAME,
     CASE WHEN TG_OP = 'DELETE' THEN OLD.id ELSE NEW.id END,
     TG_OP,
     v_actor, v_session,
     v_before, v_after,
     v_actor, now(), now());

  IF TG_OP = 'DELETE' THEN RETURN OLD; ELSE RETURN NEW; END IF;
END $$;

Triggers on audit_logs itself (append-only guard — no touch or audit trigger):

  • tr_audit_logs_bu_guard — BEFORE UPDATE → fn_append_only_guard()
  • tr_audit_logs_bd_guard — BEFORE DELETE → fn_append_only_guard()

Trigger attached to every other Tier-1 table (replaces the stub):

  • tr_<table>_au_audit — AFTER INSERT OR UPDATE OR DELETE → fn_audit_row()

2. audit_excluded_tables mutable L1 audit soft-delete

Catalogue of tables that fn_audit_row() will skip. The function checks this table at trigger time — if the source table appears here, it returns immediately without inserting an audit row. Two categories of exclusion:

  • Structural — M:M bridge tables with composite PKs (user_roles, role_permissions) have no single id column; the trigger cannot populate entity_id. Layer 1 audit columns on those tables still record who created/updated each row.
  • Volume — high-churn tables where every row change would produce an unmanageable audit log (e.g. user_sessions — every request bump of last_active_at would fire the trigger). Excluded by admin decision; Layer 1 columns provide the lightweight trail.
Columns (table-specific; uniform block also present)
ColumnTypeNullConstraintDefaultComment
iduuidNOPKuuidv7()Surrogate primary key
table_nametextNOUNIQUE—Exact table name as it appears in TG_TABLE_NAME (e.g. user_sessions, user_roles). Max length enforced by Postgres itself (63 chars).
reasontextNOCHECK IN (…)—Why it is excluded: composite_pk | high_volume | admin_decision
notestextYES——Free-form explanation

+ the 7 uniform audit + soft-delete columns.

How fn_audit_row() uses this table
-- Added at the top of fn_audit_row(), before any other logic:
IF EXISTS (
  SELECT 1 FROM audit_excluded_tables
  WHERE  table_name = TG_TABLE_NAME
    AND  deleted_at IS NULL
) THEN
  IF TG_OP = 'DELETE' THEN RETURN OLD; ELSE RETURN NEW; END IF;
END IF;
Constraints & Indexes
  • pk_audit_excluded_tables — PRIMARY KEY (id)
  • uq_audit_excluded_tables_name — UNIQUE (table_name)
  • chk_audit_excluded_tables_reason — CHECK reason IN ('composite_pk','high_volume','admin_decision')
Triggers
  • tr_audit_excluded_tables_bu_touch — BEFORE UPDATE → fn_touch_updated()
  • tr_audit_excluded_tables_au_audit — AFTER INSERT/UPDATE/DELETE → fn_audit_row()  (this table IS audited — adding/removing an exclusion is a significant admin action)
