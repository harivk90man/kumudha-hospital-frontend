v3 Schema Module 15 · Pharmacy

Pharmacy

Point-of-sale dispensing — sale header, sale lines with FEFO stock decrement, customer returns with restock logic, and return line write-offs.

Stock flow: pharmacy_sale_items INSERT → trigger fn_decrement_stock atomically decrements drug_stock.quantity_available → trigger fn_log_stock_movement appends a drug_stock_ledger row → if narcotic, trigger checks for a paired narcotic_register row in the same transaction.
Return flow: pharmacy_return_items INSERT → trigger appends drug_stock_ledger rows: return_in for restockable quantity, return_writeoff for non-restockable quantity.
Forward FKs: invoice_id → invoices (Module 17) and cash_session_id → cash_sessions (Module 18) are forward references — NULL until billing/payment modules are live.
Module 15 contents
  1. pharmacy_sales — sale header; Rx-bound or OTC; idempotency key; discount approval  signed off
  2. pharmacy_sale_items — sale lines; batch + qty + price; FEFO decrement trigger  signed off
  3. pharmacy_returns — customer return header; claim amount; cash session link  signed off
  4. pharmacy_return_items — return lines; quantity accepted at counter goes back to stock  signed off

1. pharmacy_sales mutable L1 audit L3 audit soft-delete

Sale header — one row per dispensing event. Rx-bound (linked to a prescriptions row from Module 11) or OTC (over-the-counter, no prescription required). Carries an idempotency_key to prevent double-charge on network retry. Whole-bill discounts above a configurable threshold require a second approver (bill_discount_approved_by).

v3 delta from TSD-10: tenant_id dropped. sale_date dropped — use created_at from L1 audit. All other columns kept. invoice_id and cash_session_id are forward FKs (Modules 17 and 18).

2. pharmacy_sale_items mutable L1 audit L3 audit

Sale lines — one row per drug per dispense. INSERT triggers FEFO stock decrement on drug_stock, appends a drug_stock_ledger row, and for narcotic drugs checks for a paired narcotic_register row in the same transaction. Immutable once parent sale status is dispensed.

v3 delta from TSD-10: tenant_id dropped. CASCADE from parent pharmacy_sales — if a draft sale is hard-deleted, its lines go with it. GST split kept (CGST/SGST for intra-state, IGST for inter-state — mutually exclusive).

3. pharmacy_returns mutable L1 audit L3 audit soft-delete

Customer return header — one row per return event. Always references an original sale. Refund mode determines how the customer is reimbursed: cash, UPI/card, store credit note, or via the original payment method. For OTC walk-ins, customer name and mobile are captured here (no patient record).

v3 delta from TSD-10: tenant_id dropped. refund_mode, refund_amount, credit_note_id all dropped — pharmacy return refunds are traced via non_sale_cash_movements.pharmacy_return_id in Module 18, giving full traceability from the cash session directly to the pharmacy return row. total_return_amount stays as the claim amount. cash_session_id stays as operational context.

4. pharmacy_return_items mutable L1 audit L3 audit

Return lines — one row per drug per return. The pharmacist inspects items at the counter and only accepts what can go back to stock — damaged, opened, or expired items are rejected on the spot before the return is recorded. quantity_returned is therefore always the restockable quantity. Trigger appends one drug_stock_ledger row (return_in) restoring the quantity to the original batch.

v3 delta from TSD-10: tenant_id dropped. condition, restock_quantity, writeoff_quantity dropped — counter inspection happens before the return is recorded, so all accepted quantity is always restockable. Trigger simplified to one return_in row only.
