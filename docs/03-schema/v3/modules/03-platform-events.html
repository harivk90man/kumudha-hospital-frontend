Platform Events

Domain events emitted by the application service layer — named business intents consumed by notifications, analytics, and integrations.

audit_logs vs domain_events — two separate streams:
StreamDriverNamed event?Purpose
audit_logsDB trigger on every Tier-1 tableNo — action ∈ {INSERT, UPDATE, DELETE}Forensic compliance
domain_eventsApp service-layer code (explicit emit)Yes — event_type e.g. PatientRegisteredSubscribers: notifications, analytics, integrations
A single business action typically writes to both: the DB trigger auto-generates an audit_logs row, and the service layer explicitly emits a domain_events row naming the business intent.

1. domain_events append-only L1 audit (cosmetic)

Append-only event store. Each row is a named business event explicitly emitted by a service-layer method. No trigger writes here — the app decides what constitutes a domain event and when to emit it. Partitioned monthly on created_at (same pattern as audit_logs). No FK from event_type to domain_event_types_lookup — app startup verification asserts no drift instead.

Columns (table-specific; uniform block also present — cosmetic only)
ColumnTypeNullConstraintDefaultComment
iduuidNOPK, part of composite PK with created_atuuidv7()Time-ordered surrogate PK. Sequential within each monthly partition.
event_typetextNOCHECK length 1–80—PascalCase event name, e.g. PatientRegistered, ConsultationLocked. Must match a domain_event_types_lookup.code — enforced at app startup, not by FK.
entity_tabletextYES——Primary entity this event is about (e.g. patients, consultations). NULL for cross-entity events.
entity_iduuidYES——PK of the primary entity. Polymorphic — no FK. NULL when entity_table is NULL.
payloadjsonbNO—'{}'Event payload. Shape varies per event_type; documented in domain_event_types_lookup.payload_schema. JSON shape: any object.

+ the 7 uniform audit + soft-delete columns — cosmetic only. fn_append_only_guard freezes updated_*, version, and deleted_* forever. created_by = the user who triggered the business action; created_at doubles as the partition key.

JSON shape — payload column

Shape is defined per event_type in domain_event_types_lookup.payload_schema. Representative examples:

// PatientRegistered
{"uhid": "KH-2026-000042", "full_name": "Meena Krishnan", "created_via": "reception"}

// ConsultationLocked
{"consultation_id": "uuid", "doctor_id": "uuid", "patient_id": "uuid", "diagnosis_count": 2}

// PaymentReceived
{"payment_id": "uuid", "invoice_id": "uuid", "amount": 1500.00, "mode": "cash"}

// UserProvisioned
{"user_id": "uuid", "employee_id": "EMP015", "role": "doctor"}

// LabResultReleased
{"lab_order_id": "uuid", "patient_id": "uuid", "test_count": 3, "has_critical": false}
Constraints & Indexes
  • pk_domain_events — PRIMARY KEY (id, created_at)  — composite with partition key
  • chk_domain_events_event_type_len — CHECK char_length(event_type) BETWEEN 1 AND 80
  • chk_domain_events_entity_pair — CHECK num_nonnulls(entity_table, entity_id) IN (0, 2)  — both set or both NULL; never one without the other
  • ix_domain_events_type — INDEX (event_type, created_at DESC)  — "all PatientRegistered events this month"
  • ix_domain_events_entity — INDEX (entity_table, entity_id, created_at DESC) WHERE entity_id IS NOT NULL  — "all events for patient X"
Triggers
  • tr_domain_events_bu_guard — BEFORE UPDATE → fn_append_only_guard()
  • tr_domain_events_bd_guard — BEFORE DELETE → fn_append_only_guard()

No fn_touch_updated or fn_audit_row trigger — append-only guard blocks any mutation, and domain_events is added to audit_excluded_tables (high-volume, self-describing).
