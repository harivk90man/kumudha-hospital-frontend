Identity & Auth Core

Who is this hospital, who can log in, and which sessions are active right now.

Slice 1A contents
  1. Uniform audit + soft-delete block — applies to every table in v3
  2. hospital_profile — singleton hospital identity + UHID format
  3. users — every staff account in one table (auth + HR)
  4. user_sessions — active & deleted login sessions

0. Uniform audit + soft-delete block

Every table in v3 carries the same 7-column block at the end of its row. No table is an exception — append-only tables and singletons get the columns too (they stay frozen at insert values or NULL forever; trigger enforcement keeps them honest). Uniformity over micro-optimisation.

ColumnTypeNullDefaultPurpose
created_byuuidNO—FK → users(id) ON DELETE SET NULL. Inserter.
created_attimestamptzNOnow()Insert timestamp.
updated_byuuidYES—FK → users(id) ON DELETE SET NULL. Last UPDATE-er (NULL on insert).
updated_attimestamptzNOnow()Last-update timestamp. Trigger fn_touch_updated() refreshes on every UPDATE.
versionintNO0Optimistic-lock counter. Trigger increments on every UPDATE.
deleted_attimestamptzYES—Soft-delete timestamp. NULL = live row. Live queries filter WHERE deleted_at IS NULL.
deleted_byuuidYES—FK → users(id) ON DELETE SET NULL. Who soft-deleted (set together with deleted_at).

Trigger: fn_touch_updated() (BEFORE UPDATE) sets updated_at = now() and version = version + 1 on every row UPDATE. Append-only tables (audit_logs, domain_events, etc.) carry the columns too but a separate fn_append_only_guard trigger raises an exception on any UPDATE/DELETE — so updated_*, version, deleted_* stay at insert defaults forever. Cosmetic but uniform. The 7 columns are not repeated in every per-table column spec below — assume they're present.

2. users mutable L1 audit L3 audit soft-delete

Every staff account — admin, doctors, nurses, receptionists, pharmacists, lab/radio techs — in one row each. 3. user_sessions mutable L1 audit Tier 3 audit-excluded soft-delete

Active & soft-deleted login sessions. Stores the hashed refresh token (long-lived) and session metadata, so we can support "log out other devices" and forced sign-out on password change. Access tokens are stateless JWTs — verified by signature, not stored. Audit-excluded — JWT issuance churn would explode audit_logs.

v3 deltas:
  • v2's is_active boolean dropped in favour of the uniform deleted_at. "Session is revoked" = deleted_at IS NOT NULL.
  • token_hash (access-token SHA-256) dropped. Access tokens are stateless JWTs — no DB hit per request, no per-request write. Revocation is granted via short access-token expiry (8h) + refresh-side revocation.
  • last_active_at added for idle-timeout enforcement, decoupled from absolute expiry. App writes it at most once per minute to keep the write cost trivial.
  • user_id FK changed from CASCADE to RESTRICT (matches §6 default). Hard-deleting a user must explicitly revoke their sessions first — session history has forensic value.
  • Self-FK rotated_from_session_id added for refresh-token rotation chains.

  • uq_user_sessions_refresh_hash — UNIQUE (refresh_hash) WHERE refresh_hash IS NOT NULL AND deleted_at IS NULL (excludes revoked rows that nulled the hash)

  • ix_user_sessions_idle — INDEX (last_active_at) WHERE deleted_at IS NULL (idle-timeout sweep)

What this slice locks:
  • Uniform 7-column audit + soft-delete block on every v3 table (no exceptions)
  • hospital_profile singleton structure (with address as structured jsonb)
  • users as a single auth+HR table (no users_directory split)
  • 2FA day-one via mfa_enabled + mfa_secret
  • Lockout state via failed_attempts + locked_until
  • Forced-change gate via must_change_password (boolean) — set on admin provisioning / admin reset, cleared on user-driven change. Login refuses normal sessions while set, issuing only a scoped change-password token.
  • user_sessions: stateless JWTs (no token_hash); refresh-only DB state; last_active_at for idle timeout; user_id RESTRICT; rotated_from_session_id self-FK for refresh chains
