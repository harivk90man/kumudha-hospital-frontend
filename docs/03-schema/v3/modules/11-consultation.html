1. vitals mutable L1 audit L3 audit soft-delete

Snapshot of vital signs at a point in time. Captured by the nurse at the pre-consultation desk before the doctor sees the patient. One row per OP visit (DB-enforced via partial UNIQUE); the doctor can amend the same row in-place from the consultation view if the nurse mistyped a value, with the change auto-logged via L1/L3 audit. Multiple rows are allowed only for future IP/ICU contexts where op_visit_id IS NULL (e.g. hourly BP rechecks on an inpatient). created_by (from the uniform block) identifies the recording staff; created_at is the recording timestamp — no separate recorded_by / recorded_at columns needed.

bmi is a generated column — automatically computed whenever both weight_kg and height_cm are present.

2. consultations mutable L1 audit L3 audit soft-delete

The doctor's full clinical record for one OP visit — one row per visit. Created when the doctor opens the consultation form (status = 'draft'); autosave updates this row directly. Locked when the doctor clicks Complete (status = 'locked', locked_at set) — row becomes visible to pharmacy and nursing staff and is read-only thereafter.

consultation_drafts is dropped — status on this table covers draft vs locked; autosave writes directly here, eliminating the dual-source-of-truth problem.

diagnoses is stored as jsonb (a JSON array) rather than jsonb[] — Hibernate-friendly via @JdbcTypeCode(SqlTypes.JSON). Each entry carries icd10, desc, and type.

admission_required, surgery_required, and physio_required boolean flags are dropped — captured with full detail in doctor_recommendations.

3. diagnosis_templates mutable L1 audit L3 audit soft-delete

Reusable consultation templates per specialty or diagnosis. A doctor selecting "URTI with cough" auto-fills the examination structure, common medicines, and routine tests into the consultation form — reducing typing on high-volume OPD days. Templates are created and edited by the owner or senior doctors; soft-deleting a template does not affect past consultations that used it.

4. prescriptions mutable L1 audit L3 audit soft-delete

Prescription header — one per consultation. The header status drives the pharmacy fulfilment workflow: draft while the consultation is open, active when the consultation is locked, progressing to dispensed as pharmacy fulfils the items. Drug lines live in prescription_items (CASCADE child).

Status lifecycle
  • draft → consultation in progress; items can be added or removed
  • draft → active — consultation locked; prescription visible to pharmacy
  • active → partially_dispensed — at least one item dispensed
  • partially_dispensed → dispensed — all items fulfilled
  • draft | active | partially_dispensed → cancelled — doctor reissues with corrections

5. prescription_items mutable L1 audit L3 audit soft-delete

One row per drug on the prescription. CASCADE child of prescriptions — deleting a prescription removes all its items. What was actually dispensed is tracked in pharmacy_sale_items (Module 15) — that is the source of truth for dispensing. prescriptions.status is computed from Module 15 data, not from a column on this table.

medicine_name_snapshot freezes the drug name at prescribe time — protects the printed prescription if the medicine catalogue is later renamed or retired.

Forward FK note: medicine_id references medicines(id) defined in Module 14. The FK constraint is added in the Module 14 migration.

6. doctor_recommendations mutable L1 audit L3 audit soft-delete

Non-prescription outputs of a consultation — actions the doctor wants staff to follow up on. A queue for nurses and front desk to actively work through: book a follow-up appointment, place a lab order, arrange a radiology scan, or route an external referral.

Phase 2 FK columns (physio_session_id, surgery_schedule_id, ip_admission_id) are deferred — the recommendation types (physio, surgery, admission) are still valid clinical decisions recorded as rows, just without a linked entity until Phase 2 tables exist.

At most one Phase 1 FK column is set per row — enforced by CHECK. A row with zero FK columns is valid when the recommendation is open and no entity has been created yet (e.g. follow-up appointment not yet booked).

7. consultation_drafts mutable L1 audit L3 audit soft-delete

Autosave buffer for in-progress consultations. The browser saves the doctor's work every N seconds into this table — the draft is not visible to other staff until the doctor clicks Complete and the consultation is locked. Protects against power cuts and browser crashes without exposing unfinished clinical notes.

Once the doctor restores or submits the draft, restored_at is set and the row can be cleaned up. Rows with restored_at IS NULL expire after 7 days (expires_at) — a nightly job deletes them. updated_at (from the uniform block) serves as the last-autosaved timestamp — no separate last_saved_at column needed.

Constraints & Indexes
  • pk_consultation_drafts — PRIMARY KEY (id)
  • chk_consultation_drafts_autosave — CHECK autosave_count >= 0
  • uq_consultation_drafts_visit — UNIQUE INDEX (doctor_id, op_visit_id) WHERE op_visit_id IS NOT NULL AND restored_at IS NULL  — one active draft per doctor per visit
  • ix_consultation_drafts_expiry — INDEX (expires_at) WHERE restored_at IS NULL  — nightly cleanup sweep
  • ix_consultation_drafts_doctor — INDEX (doctor_id) WHERE restored_at IS NULL AND deleted_at IS NULL  — load doctor's active drafts on login
Triggers
  • tr_consultation_drafts_bu_touch — BEFORE UPDATE → fn_touch_updated()  — updated_at serves as last-autosaved timestamp
